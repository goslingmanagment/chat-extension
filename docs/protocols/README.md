## Схемы: одна стратегия (D-06)

1. **Все схемы контрактов пишутся на `zod/mini`** (zod 4.6.5). Это одни и те же
   классы ядра zod 4, поэтому `safeParse` и `z.infer` одинаково работают в content
   script, на страницах расширения и в фоне. Классический `zod` в фоне остаётся для
   схем вендоренного SDK и внутренних нужд фона, но в `@cg/contracts` его нет: ни
   одна схема контракта не потянет классический zod в content script. DTO хаба
   (часть 2b) тоже пишутся на `zod/mini`: их разбирают и вкладка, и фон.
2. **Мост MAIN без зависимостей.** MAIN не может импортировать контракты: он
   проверяет запросы руками и повторяет нужные литералы
   (`host-chatspace/src/main/protocol.ts`), тест закрепляет их за контрактами. R09
   обязан прогнать фикстуры моста (`BRIDGE_REQUEST_FIXTURES`) через ручные проверки
   MAIN.
3. **Всё из MAIN проверяется в три ступени:** `checkBridgeFrame` (простой JSON в
   пределах) → конверт (`BridgeResponseSchema`, `BridgeEventEnvelopeSchema`) → схема
   полезной нагрузки своего типа из `bridge-messages` (`parseBridgeData`,
   `FROM_MAIN[t]`). Ответ принимается, только если его `t` совпал с типом ждущего
   запроса.
4. **Лёгкое отдельно от тяжёлого.** Конверты и списки типов лежат в лёгких
   модулях, реестры схем — в тяжёлых. Ранний старт изолированного мира импортирует
   только лёгкие (спайк M0: бюджет синхронного старта 3 мс уже под угрозой).
   Сейчас ранний бандл — 10,6 КиБ gzip (было 7,6): добавились проверка кадра и
   конверт ответа моста.
5. **Наши границы строгие:** `strictObject`, лишний ключ — отказ. Ответы хаба —
   по правилу хаба (план PR хаба §4.0): нестрогие объекты, растущие словари —
   открытые лексемы. Это забота части 2b.
6. **Типы выводятся из схем** (`z.infer`). Интерфейсы с методами (`HostPort`,
   `PreviewSendPort`, `CgEntry`) и типы-объединения входов машин написаны на TS.
7. **Фикстуры:** на каждую экспортированную схему — минимум одна верная и одна
   неверная (`test/fixtures/schemas.ts`); на каждый запрос, ответ и событие обоих
   протоколов — тоже (`test/fixtures/protocols.ts`). Тест падает, если у новой
   схемы или нового типа сообщения нет фикстур. Все id в фикстурах синтетические:
   реальные id ловит `pnpm archive-check`.

## Решения R01 (часть 1)

1. **id.** Числовые id хоста и платформы (аккаунт OnlyMonster, креатор и фан
   OnlyFans, сообщения) — строки одной формы `^[1-9]\d{0,29}$` (замечание критика
   п. 14); `Number()` к ним не применяем, величина id — не порядок. Наши id
   (операция, попытка, намерение, сессия вкладки, событие) — UUID. Ссылки хаба и
   ChatSpace (`generationRef`, локальный id записи очереди) — непрозрачные `Ref`.
   Хабовые `pageId`/`userId` — целые > 0. `ChatKey` = `хост:аккаунт:фан`.
2. **Деньги — `MoneyMills`:** целое число mills (1 mill = $0,001) типа `number` в
   пределах safe integer, со знаком — как `mills` хаба на проводе. Ни долларов с
   дробью, ни центов. Деньги AI — целые micro-USD и только в отладке.
3. **`null` = неизвестно, никогда не 0.** Необязательное поле — «не применимо».
4. **Время:** локальные моменты — epoch ms (`createdAt`, `expiresAt`,
   `observedAt`), всё, что уходит из браузера или приходит с хоста и хаба, — ISO
   8601 со смещением.
5. **Открытые лексемы** (критик п. 14): платформа, роль, флаги, фичи страниц,
   возможности хаба на проводе — строки. Клиент сужает: `narrowPlatform`
   (неизвестная платформа — страница пропускается), `narrowRole` (неизвестная роль
   → `unknown` с правами чаттера). Флаг с неизвестным именем — «выключено».
6. **MAIN не получает данных хаба и токенов** (§14 сильнее эскиза §5.3): в мост
   уходят формы `NavigationWire` (без `cause`) и `MainSendRequest` (без привязки,
   билета хаба и `actionToken`, но со сроком билета `expiresAt`: позже — `held`).
7. **Конверт моста:** `{v: 1, kind, id, t, documentEpoch, seq, payload}`; ответ
   несёт тот же `t`, `ok: true` + `data` или `ok: false` + транспортную ошибку
   (`BRIDGE_ERRORS`, без CG-кода; исходы вставки и отправки — это ответы со своими
   кодами). MAIN R00 уже говорит этим конвертом (e2e зелёный).
8. **Пределы моста:** кадр ≤ 256 КиБ UTF-8 JSON, строка и ключ ≤ 20 000, массив ≤
   1000, ключей ≤ 256, глубина ≤ 16; ключи `__proto__`/`constructor`/`prototype`,
   не-JSON значения и не простые объекты — отказ с причиной-счётчиком.
9. **Хвост переписки:** снимок моста — до 200 сообщений (`TailSnapshot`), к хабу —
   до 60 (`LiveTextTail`, предел хаба H-4c); добавлено `capturedAt`.
10. **Ошибка операции на проводе — `CgErrorWire`** (код и факты); текст ошибки
    (`CgErrorView`) строит вкладка на текущем языке — язык переключается на лету.
    В `OpView` добавлен `toneUsed` (Regenerate повторяет тон).
11. **Протокол вкладки дополнен:** `tab.register` (фон выдаёт `tabSessionId`, §5.1),
    `tab.presence` (звук и тосты «AI готово»), `op.reportShown` (телеметрия `shown`,
    §9.6). Ошибка ответа — `kind: 'res'`, `ok: false`, `CgErrorWire`. Страницы шлют
    запросы через `runtime.sendMessage`, события получают по порту `cg-page`.
12. **События фона о данных хаба — лёгкие уведомления** (`bootstrap.changed`,
    `catalog.changed`, `newcomers.changed`): данные берутся запросом.
13. **Ответы-DTO хаба пока слоты** (`pendingHubDto`): `bootstrap.get`, `catalog.get`,
    `recap.status`, `recap.read`, `spenders.board`, `spenders.stats`,
    `spenders.queue`, `feed.read`, `fan.card`, `newcomers.list`, `newcomers.claim`.
    Запросы к ним заморожены здесь; ответы замораживает часть 2b.
14. **Метрики `client_health`:** 11 имён с фиксированными границами — девять из
    §5.7 и предложения плана хаба §4.8 (`requestOverheadMs`,
    `composerInputDelayMs`). Смена границ — новая `schemaVersion` метрики.
15. **X8:** таблица переходов `SEND_ATTEMPT_TRANSITIONS` по §6.7.7; новая попытка —
    только после `held` или `notEnqueued`; `uncertain` переходит только в
    `sentObserved` по поздней связанной паре квитанции и эха.
16. **Настройки по умолчанию:** тема `host`, язык `system`, подсказки вкл; Split
    выкл; окна 100/100/25/3000; Coach — история 10, авто-рекап выкл; звуки вкл, тоны
    как в Fansly-расширении (`chime` и `double`, планка пилота X5), громкость 50;
    отладка выкл.
17. **Коды CG** — полный список прил. А в его порядке; тест сверяет его с
    `docs/architecture.md`.

## Правила отправителей (§5.4)

| Кто | Проверка фона |
|---|---|
| любой | `sender.id === runtime.id`, `sender.frameId === 0`; тип запроса известен и разрешён этому виду отправителя (`TAB_REQUESTS[type].from`) |
| вкладка | происхождение — адрес ChatSpace из `apps/extension/src/hosts.ts` (в тестовой сборке ещё стенд); после `tab.register` каждый запрос несёт свою сессию, фон сверяет её с `sender.tab.id` и документом; данные хаба — только для страниц своей привязки |
| страница | `moz-extension://<свой uuid>/<страница>.html`, страница из `EXTENSION_PAGES`; если у запроса есть `pages` — только с этих страниц |

Пароль идёт только со страниц (`session.signIn`) и нигде не пишется.
`send.*` и `op.start` — только из вкладки: мост MAIN живёт там.
