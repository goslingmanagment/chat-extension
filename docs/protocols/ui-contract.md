# Контракт UI (`@cg/contracts/vm`) и поддельный `AppClient`

Пакет работ R01, часть 2a: `architecture.md` §10.1–§10.2 плюс итоговая спецификация
интерфейса `docs/ui-design.md` (направление B «полоса», X10), включая правки контрактов
её §9.3 и мелочи §12.

`@cg/testing/app-client`. Поддельный `HostPort` для контроллеров —
`@cg/testing/host` (`packages/testing/src/scenarios/host/`).

## Решения

1. **Семь состояний у каждой модели.** `VM_STATE_SUPPORT` перечисляет, какие из них
   выдаёт контроллер вида. Все, кроме трёх, выдают все семь; быстрый переход и
   шпаргалка не зависят от хаба (нет `forbidden`/`offline`), тосты — только `ready`/`empty`.
2. **Свои слова — `Msg`, чужие данные — строки.** Деньги, возраст и время лежат в
   моделях сырыми (`MoneyMills`, ISO, мс) и форматируются только портом `I18n`.
3. **UI не собирает цель.** Он держит непрозрачные хэндлы и номера операции, варианта и
   части; `UiActionSchema` строгая, поддельный клиент отвергает лишний ключ (`persona`,
   `model`) ошибкой `ContractViolation`.
4. **Отправка — только кнопкой.** Действий «отправить всё» и «следующую сама» нет;
   «Отправить ещё раз» рисуется только по `rejected.canRetry`.
5. **Предел листа** считает `resultCap` по высоте ленты `H` из `MountPort` и зазору
   «на подложке» (ui-design §3.2); примеры спецификации — в тесте.
6. **Настройки v1:** добавлены `ui.resultStyle` (`bare` по умолчанию) и
   `onboarding.keysFooter`. Схема v1 ещё не выпущена, шаг миграции не нужен.
7. **Имя страницы для показа — `pageName`**, чтобы не путать с ключом хаба `pageLabel`.
8. **Бронь коллеги без отсчёта** (ui-design §12 п. 5); блоки Review — по AI-053 и формату
   хаба (§12 п. 6); тоны — набор паритета Casual, Flirt, Sell, Spice (id из `Tone`).
9. **Слова — общие с остальными частями** (интеграция R01): `Msg.key` — `I18nKey`
   из каталога, язык порта — `Locale`, тема и «Вид ответа» — типы `settings`, охват —
   `CoverageLevel` из `ops`; причина «Отправить» берёт текст из `SEND_REASON_KEYS`;
   статусы приветствия — `GREETING_STATUSES`. Поддельный клиент строит ошибки через
   настоящий реестр CG и каталог ru/en.
10. **Ревью R01.** Строку «Отправить» строит `previewSendStateOf` — одна таблица
    для контроллеров превью и «Новых». Хаб не называет держателя брони: у
    приветствия и брони есть «коллега» (`claim-other`, `other`) и «вы в другой
    вкладке» (`claim-elsewhere`, `elsewhere`, Hi выключен), имени нет — тексты без
    `{name}`. `FeedItemVM.at` и `.automatic` бывают `null` («неизвестно»). У панели
    фана названы источники: деньги и подписка — `fan.card`, «был N назад», био,
    списки и оценки ChatSpace — `HostFan`, риск ухода — статус удержания строки доски.
11. **Хосты монтирования ChatSpace (R09, `@cg/host-chatspace`).** Хост оверлея
    (`mounts.overlay('panel' | 'modal' | 'toast')`) — на весь экран
    (`position: fixed; inset: 0`) и **пропускает клики** (`pointer-events: none`),
    чтобы пустая часть слоя не закрывала ChatSpace. Панель, окно или тост внутри
    закрытого корня сами ставят себе `pointer-events: auto`, иначе клики проходят
    сквозь них. Док (`mounts.dock`) — в потоке над composer, кликается как есть.
    `HostPort.chatWindow(chat, max)` у ChatSpace считает по всему, что ChatSpace уже
    загрузил (не больше 200 сообщений): `max` не сужает окно.

12. **Клавиши внутри наших поверхностей (R17, ранний диспетчер §9.1).** Что должен знать
    автор поверхности:
    - Глобальные сочетания (⌘E…, ⌘K, ⌘⇧M, `?`, J/K, `]`, ⌘U, ⌘1–9, Esc «закрыть верхнее
      окно») забирает диспетчер — на `window` поверхность ничего не вешает.
    - Пока фокус внутри нашего закрытого корня, клавиши, на которые мог бы отреагировать
      ChatSpace (с ⌘/Ctrl/Alt и именованные: Enter, Esc, Tab, стрелки, Backspace…), до
      ChatSpace не доходят. Нашему элементу в фокусе приходит **копия**: событие `keydown`
      с теми же полями (`key`, `code`, модификаторы, `repeat`, `keyCode`,
      `getModifierState`), которое не выходит за наш shadow root. Это обычный `Event`, а не
      `KeyboardEvent` (`instanceof KeyboardEvent` — `false`, `isTrusted` — `false`): Firefox
      делает `KeyboardEvent` типа `keydown` составным (`composed`) независимо от параметров,
      и такая копия снова дошла бы до ChatSpace. Обработчики `onKeyDown` работают как
      обычно; `preventDefault()` на копии отменяет и действие браузера у настоящего нажатия.
    - **Копия и доверенное действие (`architecture.md` §14).** Токен записи (вставка,
      переход, отправка) выдаётся только на действие самого человека. У копии `isTrusted` —
      `false`, и всё же она **считается нажатием человека**: диспетчер делает её только из
      доверенного `keydown`, синхронно в том же обработчике, для элемента в фокусе внутри
      нашего закрытого корня; за корень она не выходит, а страница не может ни прочитать
      её, ни направить своё событие слушателю внутри корня. Enter на строке части
      (`InsertPart`) и на «Открыть и вставить» приходят **только** копией — настоящий Enter
      до нашего элемента не доходит. Поэтому обработчик клавиши не отсекает событие по одному
      `event.isTrusted`: такая проверка сломала бы вставку с клавиатуры. Правило для
      обработчика `keydown`, который ведёт к записи:
      `event.isTrusted || event[Symbol.for('cg.key.delivered')] === true`. Метку — собственное
      неперечислимое свойство только для чтения — ставит адаптер хоста (`DELIVERED_KEY_MARK`
      в `@cg/host-chatspace/isolated`); `ui` его не импортирует и называет символ сам. Для
      кликов и остальных событий правило прежнее: только `isTrusted`.
    - Обычный набор текста (буквы, цифры, пробел без ⌘/Ctrl/Alt) и клавиши во время IME
      приходят настоящими событиями, диспетчер их не трогает.
    - **Esc:** сначала его получает наш элемент в фокусе (меню, поиск, подтверждение). Если
      никто не вызвал `preventDefault()`, диспетчер закрывает верхнее наше окно. Обработал
      Esc сам — вызови `preventDefault()`, иначе закроется ещё и окно.
    - **Esc и наш диалог (`OverlayState.set('dialog', true)`).** Когда фокус вне диалога
      (например, в поле ввода ChatSpace), Esc — это его «Отмена» (ui-design §6.3). Для
      подтверждения Б2 диспетчер сам отправляет `AnswerConfirm` с `choice: 'cancel'` по
      `ResultVM.confirm` результата на экране. У любого другого диалога действие отмены
      передаёт тот, кто его монтирует: `OverlayState.set('dialog', true, action)`. Действия,
      которые вставляют, заменяют или отправляют (`InsertPart`, `OpenAndInsertPart`,
      `ReplaceMyDraft`, `SendPart`, `AnswerConfirm` кроме `cancel`), клавишей не выполняются,
      даже если их зарегистрировали. Вернуть фокус после отмены — дело самой поверхности.
    - Кто монтирует оверлей, тот сообщает об этом `OverlayState.set(surface, open)`
      (`@cg/core/application/navigation`): по нему диспетчер решает, чьи клавиши
      (HK-027, HK-029), а хост получает `data-dismissible-open`. Палитру, быстрый переход и
      шпаргалку отмечают контроллеры R17 сами (`Navigate` с `kind: 'surface'`).
    - Строка палитры несёт готовое действие; после его выполнения палитру закрывает UI
      (`Navigate` → `surface: 'palette', open: false`). Переходы в чат закрывают её сами.
    - Строка быстрого перехода несёт действие «открыть этот чат» (`Navigate` → `kind: 'chat'`
      с хэндлом чата), а не номер строки. Клик по строке и цифра под зажатым ⌘/Ctrl открывают
      чат, который в ней написан, даже если список ChatSpace с тех пор сдвинулся (открытие
      чата помечает его прочитанным на OnlyFans). Попап перечитывает список при открытии,
      ещё раз через 150 мс и при смене маршрута или аккаунтов; между этими моментами строки
      не меняются.
13. **Recap и Review без операции (1.2.0, R14).** `ShowAnalysis { view, mode }`
    открывает вид в листе дока (`sheet`), разворачивает его в окно (`expanded`,
    UI-014) или скрывает (`hidden`). `HideResult` и `ExpandResult` называют
    операцию, а у сохранённого Recap её нет (`RecapViewVM.opId = null`). Кнопка
    Recap в полосе шлёт `ShowAnalysis { view: 'recap', mode: 'sheet' }` и ничего
    не генерирует: генерация — только кнопками выбора (`RecapPickerVM.build`) и
    «↻ Обновить».
14. **Ревью R14 (1.2.0).** Вопрос Б2 и подвал отладки есть и у хода Coach
    (`CoachTurnVM.confirm`, `.debug`): у Coach своя операция на каждый ход, а
    `DockVM.result` — операция дока. Отказ запуска несёт свой момент
    (`RefusalVM.at`): «Скрыть» прячет отказ только в интерфейсе, и новый отказ
    должен отличаться от спрятанного. Точку карточки ошибки (красная или
    кольцо, ui-design §4.8) несёт сам вид ошибки — `CgErrorView.tone`; пока
    производитель её не заполняет, поверхность решает по своему чтению §4.8.
    Живой регион говорит этапы, готовность и начало и конец отсчёта до повтора
    ключами `result.announce.*`. Время, названное вместе с зоной («Обновится в
    03:00 по Москве»), печатает `I18n.formatTimeIn` в этой зоне, а не в зоне порта.
15. **ChatGoose выключен владельцем (1.3.0).** `DockVM.notice` — одна строка
    статуса у дока, который в остальном `ready`: «ChatGoose выключен владельцем»
    (главный выключатель хаба — он один на все страницы, и все функции страницы
    отвечают `disabled`) или «Расширение устарело» (сборка ниже `minVersion`
    хаба). UI рисует её баннером с кольцом, как баннеры статусов; у всех семи
    действий, у «Тон» и «Split» и у «Ещё раз» готового результата причина та же
    (`dock.reason.pageOff` или `dock.reason.clientOutdated`), `mode` —
    `copy-only`. Причина выключенного флага приходит с прежним id
    (`feature-disabled`, `no-binding`, `not-granted`) и текстом по причине хаба:
    UI печатает `reason.text` и не выводит слова из id.
16. **Страницы с одним названием (1.3.0).** Где страницы перечисляют или
    выбирают («Персоны», «Аккаунт», «Аккаунты», popup), рядом с названием —
    платформа и метка страницы хаба: `PageTagVM`. Платформу UI печатает словом
    (`onlyfans` → «OnlyFans», `fansly` → «Fansly»), незнакомую лексему — как есть.
    Вид — «Lora Vie · OnlyFans · lora-vip»: название читается первым, метка —
    приглушённо. В имени выбора персоны и в строке «на ней: …» каталога метка
    стоит в скобках: «Lora Vie (OnlyFans · lora-vip)».
17. **Проверка сохранённых Recap не прячет кнопки сборки.** Пока `RecapPickerVM.view`
    — `loading` («Проверяю сохранённые Recap…») и хотя бы одна кнопка `build`
    доступна, лист показывает строку этапа и обе кнопки: чтение говорит только, что
    уже сохранено, а при медленной связи с хабом оно длилось 20 секунд. Enter в это
    время не собирает (нужен клик), чтобы не тратить полный Recap на фана, у
    которого он уже есть. Если кнопки недоступны (чат ещё грузится) — прежняя
    строка загрузки.
18. **Строки-остатки таблицы тиров (1.4.0).** У строки статистики Spenders может
    быть `remainder`: `untiered` — «Без тира», `unattributed` — «Не распределено».
    UI берёт подпись по этому полю (`stats.shelf.*`), а не по пустым границам:
    таких строк две, и у них разные id. Строки с границами подписаны по
    `range`, как раньше; порядок — от самого дорогого тира вниз, остатки в конце.
19. **«Ждут ответа» без очереди хаба (1.5.0).** Если у доски есть
    `waitingFallback`, список под фильтром «Ждут ответа» — локальный: только уже
    загруженные строки доски. UI показывает над списком карточку ошибки
    (`waitingFallback.error`, код виден) с кнопкой «Повторить»
    (`waitingFallback.retry`) и строку `spenders.waitingLocal`. Сам список остаётся на
    экране.
20. **Причина `runtime-unreachable` (1.5.0).** Порт вкладки оборвался, а расширение
    то же самое: док — в статусе `hub-down` с ошибкой `CG-RUNTIME-UNREACHABLE`
    (плашка «Расширение не отвечает» с «Повторить», текст — из реестра ошибок, не
    «хаб ответит»), кнопки приглушены с причиной `runtime-unreachable`. Карточка
    «Перезагрузить вкладку» (`reload-needed`) — только для настоящего обновления.
21. **Окно превью для «Онлайн» (1.9.0, CS-030, X24).** Превью фана, которого «Онлайн»
    палитры показал онлайн, — своё окно: поверхность `preview` (`MOUNT_SURFACES`) на
    модальном слое, вид `{ of: 'preview', from: 'palette' }`. Монтирует его тот, кто
    монтирует оверлеи, пока открыт оверлей `preview` и `OverlayState.previewFrom()` —
    `palette`; превью из Spenders и «Новых» остаётся частью своего окна. Модель та же, что в
    Spenders; соседи (`neighbors`) — список, который показала палитра, в её порядке.

## Сценарии

Тест целостности проверяет: каждая тема §10.2 п. 7 покрыта, каждый вид достигает каждого
своего состояния, все девять состояний «Отправить», все статусы дока (оба кода
`host-degraded`), все состояния приветствия и брони, все действия внутри моделей проходят
`UiActionSchema`, у каждой ошибки есть тексты реестра, id только синтетические.
