# R20: ChatGoose на fansly.com — план работ

Версия 2, 2026-10-12 (после первого ревью astra). Что строим — `docs/fansly/spec.md` (требования `FS-*`);
факты о странице — `docs/research/fansly-web.md`; решения владельца — X33 в `docs/decisions.md`.

## 0. Правила

- **Один PR — одна небольшая задача.** Draft; перед Ready — `pnpm check` и `pnpm e2e` локально (e2e — в
  Docker, `tools/ci/e2e-docker-local.sh`); в Ready — один раз. Работа — в отдельном worktree.
- **Ничего не включается при слиянии.** Всё Fansly-специфичное — за флагами страницы в хабе
  (`chatExtensionFeatures`) и за «Включить Fansly» в расширении. Пока флаги выключены, выпуски ChatSpace идут
  как обычно и Fansly-кода у чаттеров ChatSpace не касаются.
- **ChatSpace не ломаем.** Каждый PR, который трогает общий код (`core`, `ui`, `contracts`, `hub`, `host-kit`),
  держит зелёными все e2e ChatSpace и его бюджеты размера.
- **Хаб — отдельный репозиторий**, свои PR по правилам `docs/hub-pr-plan.md`: каждый PR при слиянии ничего не
  включает; SDK в расширение — только из выложенного коммита.
- **Живой Fansly** — только на тестовой переписке владельца и только с его участием. Чтения — без
  ограничений этого плана; записи в поле ввода и вложения — только в раннем smoke (этап 3в), без отправки.
- **Бюджеты — с первого этапа.** Каждый этап, который добавляет код на страницу Fansly или в фон, проверяет
  свои бюджеты из §7 спецификации против базы старого (этап 3г).

- **1а.** `docs/fansly/parity-matrix.md`: каждая строка паритета, которая касается Fansly — строки `Fansly` и
  `пилот + Fansly` манифеста, пилотные строки ChatSpace, если их функция есть на Fansly, NF-001…039, AI-032…037,
  AI-110…115, AI-143…148, VA-001…006, SN-017…020, SP-036…041, — и новые строки для E149, E152, E155. Для каждой:

  AI-143…148 закрываются проверкой сформированного контекста хаба (HF-7), а не переносом чтений.
- **1б.** Гейт: `pnpm parity` падает, если у строки с хостом Fansly нет названного теста к этапу, который её
  закрывает (сейчас `pnpm parity:coverage` — только отчёт). Измерение «хост» в манифесте.
- Приёмка: матрица совпадает с манифестом; гейт ловит строку без теста.

### Этап 3. Спайк, подписанные сборки, ранний smoke, база

**3а. Стенд и код** — отчёт `docs/fansly/spike.md`, правки спецификации, если ответы её меняют:
1. Navigation API в Firefox ≥ 142; пропускают ли сигналы FS-RTE-2 смену адреса без изменений DOM и A→B→A до
   вызова наблюдателей — решает FS-RTE-3.
2. Регистрируется ли MAIN на `document_start` через `scripting.registerContentScripts`.
3. Не меняют ли Proxy над XHR и WS ответы, статусы, тайминги и порядок обработчиков страницы.
4. Какие события сокета означают удаление и правку сообщения, как приходят пакеты (по бандлу и стенду).
5. Ленивый relay во вкладке контейнера с прокси (стенд прокси, как в E149).

**3б. Подписанные тестовые сборки** (unlisted, подпись — владелец): бывает ли `webRequest` опциональным в
Firefox MV3; держит ли обновление сборка с хостами Fansly в манифесте; будит ли слушатель `webRequest` event
page — решает FS-PERM-2.

**3в. Ранний smoke владельца** на тестовой переписке Fansly, с владельцем, без отправки:
- `execCommand('insertText')` из content script в настоящее поле Fansly: модель, кэш черновика, отмена, IME;
- передача файла в поле без отправки; как подтверждает войс старое расширение (якоря `waveform` нет);
- HF-1: `account.id` против `external_page_id`.

**3г. База старого 2.8.1** — сценарий §11 архитектуры на Fansly (открыть, 20 переключений, набор, час
простоя), Firefox Profiler, winpc и Mac, данные и настройки зафиксированы (`tools/perf/README.md`); итоги —
в `docs/fansly/baseline.md`; бюджеты §7 спецификации утверждаются по ней.

## 3. Риски

| Риск | Чем закрываем |
|---|---|
| Вставка в чужой чат (P1) | FS-INS-1, e2e на 200 переключений |
| Тихая потеря хвоста | §3 спецификации, HF-8, e2e по хвостам, учёт долей |

| Fansly переходит на `withFetch` | якоря ответов покажут; запасной наблюдатель `fetch` |

| Запрос через чужую сессию или прокси | relay привязан к вкладке и документу, прямого запасного пути нет |
| AI беднее старого | HF-5…HF-8, проверка сформированного контекста |
| Память фона и MAIN | пределы FS-TAIL-5, ленивые сервисы, журнал «Новых» в IndexedDB, сценарий 10 вкладок |
