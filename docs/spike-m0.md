# Спайк M0: итоги

Дата: 2026-10-03. Пакет работ R00 «Каркас», ветка `goslingmanagment/r00-scaffold`.
Где мерили: Mac владельца, Node 26.7.0, pnpm 10.33.1, Firefox 157.0 без окна.
Что проверяли — `docs/architecture.md` §3 «Спайк M0 проверяет до основной работы».

## Коротко

- **Все четыре проверки пройдены.** Откатываться не пришлось: остаёмся на
  **Node 26** и **Preact 11**.
- Проверка идёт автоматически: `pnpm e2e` ставит тестовую сборку расширения в
  Firefox без окна и проходит 7 сценариев на нашем локальном стенде за ~7 секунд.
  `pnpm check` (типы, линт, тесты, сборка, `web-ext lint`, размеры, инварианты,
  архив) — зелёный за ~10 секунд после чистой установки.
- **Не проверено:** пробная подпись в AMO (нужны ключи и ваше «да»), настоящий
  ввод через метод ввода (IME — его не эмулирует WebDriver), замеры на winpc,
  обновление через фид, живой ChatSpace (ждёт вашего входа в dev-профиль).

Что всплыло:
- `web-ext lint` даёт три предупреждения, ошибок нет. Два — `innerHTML` внутри
  самого Preact (его поддержка `dangerouslySetInnerHTML`; мы её не используем,
  гейт запрещает), одно — `import()` с переменной (так грузятся ленивые чанки).
  Для выпуска это не помеха; `pnpm check` падает только на ошибках линтера.
- В WebdriverIO 9.32 команда `uninstallAddOn` сломана: шлёт GET с телом, и
  `fetch` в Node такое отвергает. Это ошибка WebdriverIO, не Node 26 (так ведёт
  себя любая современная Node). Обошли командой BiDi `webExtensionUninstall`.
- geckodriver WebdriverIO скачивает сам при первом запуске (нужен интернет один
  раз); скрипты установки пакетов `geckodriver`, `edgedriver`, `esbuild` не нужны
  и выключены.

## Проверка 2. Preact 11 в закрытом Shadow DOM — пройдена

На стенде (наша страница с той же структурой поля ввода, что у ChatSpace:
`div.relative > .composer-frame > полоса > слот переводчика`):

- **Док** встаёт в поток первым ребёнком корня рамки, над полем ввода, как в
  §6.3. Страница его shadow root не видит (`shadowRoot === null`).
- **Стили** через `adoptedStyleSheets` работают в content script Firefox сразу;
  запасной `<style>` не понадобился. Строгий CSP страницы им не мешает.
- **Замеры** (точность таймера в Firefox — 1 мс, поэтому «0» значит «меньше 1 мс»):

  | Что | Время |
  |---|---|
  | загрузка чанка дока (`import()`) | 2–3 мс |
  | первая отрисовка дока | 0–1 мс |
  | список на 1000 строк, первая отрисовка | 5–7 мс |
  | тот же список, обновление всех 1000 строк | 2–5 мс |
  | от отрисовки до следующего кадра | 0–3 мс |
  | синхронный старт изолированного скрипта | ≤ 1 мс (бюджет на winpc — 3 мс) |

  Список простой, без виртуализации: настоящие длинные списки будут
  виртуальными (не больше 150 строк в DOM, §10.1, пакет R13).
- **Фокус:** клик по полю внутри закрытого корня ставит фокус туда (для
  страницы активен наш хост, внутри корня — поле ввода); набор «hi Привет»
  дошёл. С клавиатуры: из поля ввода стенда Shift+Tab переводит фокус в наше
  поле (текст выделяется, как обычно при Tab), дописанный «!» на месте.
- **IME** автоматически не проверить: WebDriver шлёт готовые символы, а не
  события метода ввода. Кириллица набирается; обработчики
  `compositionstart`/`compositionend` в отладочном отчёте есть — проверим руками
  в dev-профиле.
- **Размеры** (gzip, бюджеты §11):

  | Часть | Размер | Бюджет |
  |---|---|---|
  | мост MAIN | 0,78 КиБ | 5 КиБ |
  | тап WebSocket (тоже MAIN) | 0,48 КиБ | 5 КиБ |
  | ранний старт изолированного мира | 7,45 КиБ | 30 КиБ |
  | первый чанк дока вместе с Preact | 6,09 КиБ | 45 КиБ |

- Откат на Preact 10.29.8 не понадобился. Код UI — только функциональные
  компоненты и хуки, без `preact/compat` (линт это запрещает).

## Проверка 3. Ленивый ESM-чанк в Firefox MV3 — пройдена

- `import('moz-extension://…/lazy/dock.js')` из изолированного скрипта работает.
  Второй чанк (список спайка) берёт Preact из уже загруженного общего чанка —
  Preact грузится один раз.
- В `web_accessible_resources` — только файлы `lazy/`. Чанк спайка есть только в
  тестовой сборке; в выпускной — один чанк дока.
- **Строгий CSP страницы** (`script-src 'self'`, `style-src 'self'`, без inline)
  не мешает ни импорту чанков, ни стилям, ни мосту.
- **Вкладка, открытая до переустановки расширения.** Проверяли удалением и
  повторной установкой поверх открытой вкладки:
  1. При удалении Firefox молча убивает старые скрипты: ни события порта, ни
     ошибки. Их DOM (док, оверлей) остаётся на странице мёртвым.
  2. При установке Firefox сам вставляет скрипты манифеста в уже открытую
     вкладку — но поздно, когда документ уже загружен, а не на `document_start`.
  3. Новый экземпляр убирает мёртвые хосты прошлого (сделано в R00) — док
     на странице один.
  4. Тап WebSocket прошлой установки остаётся в странице; новый тап в такую
     вкладку не встаёт (регистрация действует только на новые документы).

  Вывод для R09: «скрипт пришёл поздно» (`readyState` не `loading` при старте)
  = вкладка старше расширения → баннер «ChatGoose обновился — перезагрузите
  вкладку» (UP-009, `CG-RUNTIME-RELOADED`). Настоящее обновление через фид
  проверим на первом выпуске (R19); Firefox обрабатывает его так же, как
  установку, но своими глазами мы это ещё не видели.

## Проверка 4. MAIN на `document_start` и динамическая регистрация — пройдена

- **Мост MAIN из манифеста** стартует, пока документ ещё грузится
  (`readyState = loading`), ставится быстрее 1 мс (бюджет — 1 мс), отдаёт
  изолированному скрипту `MessagePort` через рукопожатие §5.3. Ответы моста
  изолированный мир проверяет схемой `zod/mini`; подделку отбрасывает (тест).
- **Динамическая регистрация** `scripting.registerContentScripts({world: 'MAIN',
  runAt: 'document_start', persistAcrossSessions: true})` в Firefox 157 работает:
  после регистрации тап уже стоит, когда в `<head>` выполняется первый скрипт
  страницы. `new WebSocket(...)` остаётся родным: `instanceof`, прототип и
  статические константы те же, счётчик тапа видит сокет.
- В выпускной сборке тап не регистрируется: флага `wsTap` из bootstrap ещё нет
  (R08), поэтому он выключен. Тестовая сборка регистрирует тап только для
  локального стенда.

## Что сделано не совсем как в architecture.md

1. **«Первый чанк дока» — отдельный ESM-чанк**, который изолированный скрипт
   грузит сразу, как нашёл поле ввода. Сам content script остаётся без UI
   (7,45 КиБ). Так Preact один на док и на все ленивые экраны. В §11 это и так
   две разные строки бюджета; здесь это стало устройством сборки.
2. **Тестовая сборка — отдельное дополнение:** своё имя «… (тест)», свой id
   `chat-extension-test@gosling.agency`, без адреса обновлений. Так она никогда
   не обновится выпуском и не смешает хранилище с ним.
3. **`pnpm build` = `wxt zip -b firefox --mv3`** (внутри та же `wxt build`), чтобы
   у `archive-check` были настоящие XPI и архив исходников для AMO.
4. **Хоткеи вендорены из того же коммита хаба, что и SDK** (`44b05ad5`, он сейчас
   в проде). Файлы хоткеев там не менялись с `a667c62b`, откуда их брали
   Fansly-расширение и десктоп: sha256 совпадает (`953c6236…`), отличается только
   записанный коммит.
5. **Убираем мёртвые хосты прошлой установки** (`removeStaleHosts`) уже в R00 —
   иначе после переустановки на странице было два дока. Это кусочек R09.
6. **Иконки 48/96/128** — гусь Fansly-расширения с синим значком, чтобы два
   расширения не путались на панели. Окончательный вид — на ваше усмотрение.

## Что ещё заметили

- WXT (`ContentScriptContext`) сообщает о старте content script через
  `window.postMessage`. Страница может подделать такое сообщение и выключить наш
  скрипт — это только отказ в работе, без утечки. Решит R09: выключить это
  сообщение (`noScriptStartedPostMessage`) или проверять самим.
- Таймер Firefox округляет до 1 мс, поэтому быстрые операции надо мерить пачкой
  повторов; для бюджетов §11 этого хватает, для профиля — Firefox Profiler.

## Как повторить

```sh
pnpm install --frozen-lockfile
pnpm check   # типы → линт → тесты → сборка → web-ext lint → размеры → инварианты → паритет → архив
pnpm e2e     # тестовая сборка + Firefox без окна; замеры — в .cache/e2e/spike-m0.json, снимок — .cache/e2e/stand-dock.png
```
