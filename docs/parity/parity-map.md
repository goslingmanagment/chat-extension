**Колонки:**
- «Было» — цель в чек-листе: пилот / Fansly / ChatSpace / не нужно / решение владельца.
- «Итог» — цель после сведения.
- «Модуль» — где живёт реализация:
  - `core/<x>` — `packages/core/src/domain/<x>`;
  - `core/app/<x>` — `packages/core/src/application/<x>`;
  - `core/svc/<x>` — `packages/core/src/services/<x>`;
  - `host-chatspace/main/…` — мост MAIN, остальное `host-chatspace/…` — изолированная часть;
  - `ui/…`, `hub/…`, `platform/…`, `testing/…` — одноимённые пакеты;
  - `apps/extension` — точки входа и манифест.
- «Пакет» — пакеты работ R00–R20 (`architecture.md` §16). Первый — основной владелец строки.
- «Этап» — M0–M7 (`architecture.md` §17), F — фаза Fansly.
- «Пометка»:
  - **перекласс.** — цель изменилась против чек-листа;
  - **решено** — строка ждала владельца и закрыта ответом или значением по умолчанию;
  - **уточнено** — цель та же, но поведение изменено решением раундов 3–4.

  В скобках — откуда решение: A, B (r3 — раунд 3), владелец, X8, r4 — обязательные решения раунда 4.

Строки «не нужно» и «убрано владельцем» тоже проверяются: в R02 есть отрицательная проверка, что убранная функция не вернулась (реестр исключений в R01).
