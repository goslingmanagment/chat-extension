# OnlyMonster ChatSpace: можно ли заменить им наш десктоп для OnlyFans

> Дата: 2026-10-02. Что сделано: живое наблюдение ChatSpace в Chrome владельца через
> протокол отладки браузера (только чтение), разбор клиентского кода ChatSpace 0.167.0
> (49 файлов, около 240 тыс. строк после форматирования), документация OnlyMonster,
> прототип панели в отдельной вкладке, проверка вживую на тестовом чате владельца,
> инвентаризация нашего Fansly-расширения и десктопа. Подробные отчёты со ссылками
> «файл:строка» лежат в [`onlymonster-chatspace/`](onlymonster-chatspace/).

## Цель

Владелец нашёл веб-версию чата OnlyMonster — ChatSpace (`chat.onlymonster.ai`). Если она
годится как основа, нам не нужно держать свой Electron-клиент для OnlyFans. Чат, медиа,
PPV и синхронизацию делает OnlyMonster, а мы добавляем свой AI расширением браузера, как
уже сделано на Fansly.

Вопросы владельца:
1. Можно ли сделать полный аналог Fansly-расширения под ChatSpace?
2. Какие плюсы и минусы относительно десктопа?
3. Делать ли новое расширение с нуля, с хорошей архитектурой, а потом перенести туда Fansly?

## Коротко

1. **Да, полный аналог сделать можно, и технически это проще, чем на Fansly.**
   - Защиты от надстроек у ChatSpace нет.
   - Всё нужное доступно прямо из страницы: какой чат открыт, история, данные фана, траты.
   - У ChatSpace есть свой внутренний мост для вставки текста в поле ввода. Его сделали для собственного переводчика OnlyMonster.
   - Прототип панели ChatGoose внутри ChatSpace проверен руками: панель читает контекст и вставляет черновик.
   - AI-кнопки можно подключить к хабу так же, как в десктопе: клиент шлёт только ссылки, промпт и контекст собирает хаб. Доработок хаба для первого запуска не нужно.
2. **Плюсов больше, чем минусов, но есть три вопроса, которые надо закрыть до старта:**
   - **Правила OnlyMonster.** Пункт 2.1(d) запрещает reverse engineering, нарушение грозит блокировкой аккаунта.
   - **Браузер.** Fansly-расширение работает только в Firefox, а работу ChatSpace в Firefox я не проверял. В Chrome вне магазина расширение ставится только на управляемые компьютеры, а сам магазин, скорее всего, не пропустит расширение для взрослой платформы.
   - **Свежесть AI-контекста.** Сейчас хаб берёт переписку для AI из своего архива, а архив пополняется вебхуками OFAPI с задержкой в минуты. ChatSpace же получает сообщения меньше чем за секунду.
3. **С нуля — да, это правильное решение, с одной поправкой: «с нуля» относится к оболочке, а не к контрактам.**
   - Заново пишем оболочку расширения, адаптеры и интерфейс.
   - Берём то, что уже проверено: AI на хабе с персонами и промптами, `@kernel/sdk`, схему хоткеев `@chatgoose/hotkeys`, чистые модули из `packages/shared`, при желании — React-поверхности десктопа.
   - Архитектуру закладываем сразу на два хоста: ChatSpace (OnlyFans) и fansly.com. Fansly тогда переезжает вторым адаптером, а не прикручивается сбоку.
   - Старый бандл Fansly не переносим: в нём нет слоя адаптера, классы по 4–5 тысяч строк, глобальный CSS.

Масштаб, о котором речь (данные прода):
- десктопом последние недели пользуются **1–2 чаттера на двух OnlyFans-страницах**: 200–900 отправок и 130–900 AI-генераций в неделю;
- Fansly-расширением пользуются 3–5 чаттеров на шести страницах.

Держать ради этого Electron с подписями, Windows-сборками, своим фидом обновлений и инцидентами — дорого.

## 1. Как устроен ChatSpace

```
OnlyFans  ⇄  сервер OnlyMonster  ⇄  REST onlymonster.ai/api/v0/…   ⇄  chat.onlymonster.ai
             (держит сессию            + WebSocket                     (вкладка обычного
              креатора, прокси,          wss://onlymonster.ai/            браузера)
              медиа-прокси)              api/chat-space/ws
```

- **Сессию OnlyFans держит сервер OnlyMonster, а не браузер.**
  - Вкладке не нужен вход в OnlyFans, прокси и антидетект.
  - Чтение и отправка идут через бэкенд OnlyMonster, кредиты OFAPI на это не тратятся.
  - Браузер к onlyfans.com не обращается: медиа идёт через подписанный прокси OnlyMonster `pw365.ompcdn.com`.
- **Реальное время.** События WebSocket — по сути пересланные события самого OnlyFans: внутри `account_new_message` лежит сырой объект пользователя OnlyFans. Новое сообщение фана приходит во вкладку меньше чем за секунду.
- **Стек.** Vue 3.5, Vite, Tailwind и PrimeVue, Pinia (хранилища состояния) и Pinia Colada (кэш запросов), редактор TipTap, вход через Clerk.
  - Около 5 МБ JS и CSS. Вкладка занимает примерно 40–50 МБ памяти JS и около 5 тыс. DOM-узлов, из кэша загружается меньше чем за секунду.
- **Скорость данных.** Обычные запросы отвечают за ~0,4 с, список чатов за ~1,7 с. История переписки идёт живым запросом к OnlyFans: медиана 3,6 с, максимум 11 с. Открытый чат ChatSpace кэширует на 10 минут.
- **Вход и права.** У каждого чаттера свой аккаунт OnlyMonster. Токен для API живёт 60 секунд и обновляется сам. Доступ к ChatSpace, загрузке медиа, рассылкам, скрытию чатов, unsend и работе только в смену задаётся правами OnlyMonster.
- **Платформы.** В интерфейсе OnlyFans и ранняя версия Telegram (`telegram_v2`).
  - Наш Fansly-аккаунт API уже возвращает, но ChatSpace его отфильтровывает.
  - В правах и флагах уже есть Fansly, Fanvue и Snapchat. В документации: «поддержка других платформ будет позже».
- **Темп изменений.** Бета с 7 августа 2026. Версия 0.103 вышла 4 сентября, 0.167 — 1 октября: около 60 версий за 4 недели, по несколько релизов в день. Для любой надстройки это главный факт.
- **ChatSpace сделан прежде всего для OM Browser** — десктоп-приложения OnlyMonster на Electron. В коде есть мост `window.OM_WINDOW`: встроенная панель, отдельное окно, системные уведомления, колонка нативных виджетов.
  - В обычном браузере этого моста нет, ChatSpace работает в веб-режиме.
  - Карточка фана справа («Fan's Overview», «Fan Notes») — это виджеты OM Browser. В обычном браузере колонка пустая.
  - Новая боковая панель ChatSpace (вкладки Insights, Sales, Templates, Notes, Recap, AI) стоит за флагом `sith.cor-2363.side-panel`, у нашей организации он выключен. Вкладки Recap и AI в коде пока пустые.
  - **Расширения браузера в OM Browser поставить нельзя.** Наше расширение будет работать, только если чаттер открывает ChatSpace в обычном Firefox или Chrome.

## 2. API и WebSocket

**REST.** Адрес `https://onlymonster.ai/api/...`, заголовок `Authorization: Bearer <токен Clerk>`, CORS открыт для всех источников. HTTP-клиент — библиотека ky, таймаут 40 с. GET повторяется на 408/429/5xx, POST и PATCH не повторяются никогда. Около 125 пар «метод + путь», полный каталог в [api-catalog.md](onlymonster-chatspace/api-catalog.md).

| Что | Эндпоинты |
|---|---|
| Аккаунты, права | `GET /api/v0/accounts`, `GET /api/user/permissions`, `GET /accounts/{acc}/settings` |
| Список чатов | `GET /accounts/{acc}/chats?limit=10&offset&filter&list_id&query&order&force` (страницы по 10; `force=true` — обойти кэш OnlyMonster), `/chats/counts`, `/chats/badges` |
| История | `GET /accounts/{acc}/chats/{fan}/messages?limit=10&cursor=…` |
| Отправка | `POST /accounts/{acc}/chats/{fan}/messages` |
| Прочтение | `POST …/platforms/onlyfans/chats/mark-as-read` (все чаты), `DELETE …/platforms/onlyfans/chats/{fan}/mark-as-read` (= пометить непрочитанным) |
| Набор текста | `POST /accounts/{acc}/chats/{fan}/typing` |
| Фаны | `…/platforms/onlyfans/fans?fan_ids=…`, `/fans/{fan}/insights`, `/fans/{fan}/info`, `POST …/fans-online` |
| Деньги | `/api/stats/platforms/onlyfans/buying_power`, `/api/stats/accounts/{acc}/fans/transactions/latest`, риск чарджбэка |
| Команда | `…/logs/messages/senders` (кто из чаттеров отправил), `…/logs/messages/unsent` (архив отозванных), `GET /users` |
| AI | `/suggestions/accounts/{acc}/toolbar`, `POST /suggestions/accounts/{acc}/chats/{fan}/generate`, `/copilot/…` (Mimic), `/translator/…` |

**Отправка сообщения.**
1. Enter или кнопка Send ставят сообщение в очередь `pendingMessages`. На аккаунт уходит строго по одному сообщению, в чате ждёт не больше 50, таймаут 30 с.
2. Затем идёт `POST …/messages` с телом `{text (HTML из TipTap), is_copied, is_ai_generated, internal_template_id, previous_message, platformMetadata{mediaFiles, previews, price, lockedText, giphyId, replyToMessageId, …}}`.
3. Ключа идемпотентности нет. Подтверждение — эхо по WebSocket, сверка по тексту без HTML. Автоповтора нет нигде — так же, как в наших правилах.
4. Если включён автоперевод OnlyMonster, текст перед отправкой переводится и подменяется в поле.
5. Пока чат ведёт Mimic (их AI-бот), отправка заблокирована. Серверный Message Guard может отклонить сообщение по запрещённым словам и темам.

**WebSocket.**
- Один сокет на вкладку, подписка `subscribe_account` на аккаунт целиком. Токен Clerk кладётся в каждое сообщение клиента. Heartbeat нет; при обрыве — переподключение с бэкоффом до 30 с и волной перезапросов.
- В клиенте объявлено 35 событий сервера. Основные:
  - `account_new_message` — полное сообщение, HTML, медиа, цена, `is_from_fan`;
  - `account_message_deleted`;
  - `account_fan_typing` — каждые 3–4 с, пока фан печатает;
  - `account_fan_ppv_purchased`, `account_fan_tip_received`;
  - `account_messages_summary` — счётчики непрочитанного, приоритетных и чаевых;
  - события шаблонов, меток, Mimic, прав.
- Событий «фан прочитал», «фан онлайн» и «сообщение изменено» нет. Онлайн фанов ChatSpace узнаёт опросом.

**Публичный API OnlyMonster** — отдельный, официальный.
- Адрес `omapi.onlymonster.ai`, ключ в `x-om-auth-token`. Лимиты: 25 запросов в секунду на организацию, 1 в секунду на аккаунт для чатов.
- Что есть: история и отправка сообщений, транзакции, подписки, чарджбэки, vault, участники организации.
- Вебхуки: `chat.message` (входящие и исходящие), `fans.ppv.purchased`, `fans.tip.received`, `fans.subscription.new_subscriber`, Message Guard, vault.
- Это возможный источник данных для хаба вместо части OFAPI. К расширению отношения не имеет.

## 3. Прочтение чата — проверено вживую

Это был главный открытый вопрос. В OnlyFans любое чтение тела переписки сразу показывает фану «прочитано» — мы проверяли это на OFAPI в июне.

- **Что делает код ChatSpace.**
  - При открытии OnlyFans-чата клиент только обнуляет счётчик у себя в кэше и сам команду «прочитано» не отправляет.
  - Явное «прочитать при открытии» включено только для Telegram.
  - Фонового обхода чужих чатов нет: история грузится только для открытого чата.
- **Что показала проверка.** Тестовый чат владельца — переписка VIP с бесплатной страницей, фан из `P3_SEND_TEST_FAN_ID`:
  1. Пометил чат непрочитанным через ChatSpace. Счётчик в OnlyFans стал 1 (проверял свежим списком, `force=true`).
  2. Открыл чат в ChatSpace. Ушли только два запроса истории.
  3. Через 12 секунд счётчик в OnlyFans стал **0**. Чат вернулся в исходное состояние.
- **Вывод.** Открыть чат в ChatSpace — значит прочитать его в OnlyFans, как и в самом OnlyFans. Это честное поведение: человек сам открыл чат. Но для расширения из этого следует жёсткое правило: **никогда не загружать историю чатов, которые человек не открыл** (для доски Spenders, саммари, превью и т.п.). Данные других фанов брать только из архива хаба, а данные открытого чата — из памяти страницы.

## 4. Как встроиться

Защиты нет:
- политика безопасности страницы (CSP) запрещает только встраивание в iframe;
- проверок `isTrusted`, детекта расширений, SRI и обфускации нет;
- телеметрии OnlyMonster, которая записывала бы чужой интерфейс, нет.

| Точка | Как достать | Что даёт | Устойчивость к их релизам |
|---|---|---|---|
| Экземпляр приложения | `document.querySelector('#app').__vue_app__` | вход во всё остальное | высокая |
| Роутер | `$router.currentRoute` — `/accounts/:accountId/chats/:chatId`; `afterEach` | какой аккаунт и какой фан открыт, смена чата | высокая (всего 2 маршрута) |
| Хранилища Pinia | `$pinia._s.get('chats' / 'chatList' / 'pendingMessages' / …)`, `store.$subscribe`, `$onAction` | состояние чатов, онлайн, «печатает», факт отправки | средняя: имена — строки и переживают сборку, но их могут переименовать |
| Кэш запросов | ключи `["chatMessages",acc,fan]`, `["fansMap",acc]`, `["fanInsights",acc]`, `["onlyfansBuyingPowers"]`, `["onlyfansLastPayments",acc]`, `["ofMessageSendersMap",acc]` | история, фан, траты, buying power, оценки, кто отправил — без своих запросов | средняя: ключи стабильны, форма объектов может меняться |
| Мост поля ввода | `[data-id="browser-composer-translator"].__omComposerBridge` → `setText`, `insertText`, `focus`, `insertMessage` | вставка нашего текста их же способом; слот для нашей кнопки над полем | высокая: это их интерфейс для внешнего кода |
| Редактор (запасной путь) | `.ProseMirror.editor` (TipTap) | вставка и очистка | высокая |
| Разметка | около 225 атрибутов `data-testid`, `aria-label` у кнопок | места для кнопок и панелей | высокая |

**Проверено руками на тестовом чате владельца** (ничего не отправлялось):
- вставка текста делает Send активной и сохраняет черновик ChatSpace (`chat-space:draft:of:36408:518588958`). Уходит `POST …/typing`, то есть фан видит «печатает…», как при ручном наборе;
- очистка возвращает всё обратно;
- прототип панели в Shadow DOM показывает фана, траты, buying power, оценки, последнее сообщение фана и обновляется по событиям хранилищ.

**Хоткеи.** Наша схема пересекается с ChatSpace:

| Наша клавиша | Что делает у них |
|---|---|
| ⌘/Ctrl+E (Reply) | inline-code TipTap |
| ⌘/Ctrl+I (Fix) | курсив TipTap |
| ⌘⇧S (Recap, mac) | зачёркивание TipTap |
| Ctrl+Alt+S (Recap, Windows) | автоперевод OnlyMonster |
| Esc | закрывает вкладку чата |

Лечится одинаково: слушатель `keydown` на `window` в фазе capture, поставленный раньше приложения (`document_start`), с `preventDefault` и `stopImmediatePropagation` для своих сочетаний.

**Куда ставить интерфейс:**
- свой Shadow DOM вне `#app` (панель справа или выдвижная). Vue его не трогает, стили изолированы;
- маленькие кнопки — в слот моста над полем ввода;
- в виртуальные списки сообщений и чатов и внутрь редактора ставить нельзя.

Тема берётся из класса `dark` на `<html>` и переменных `--color-om-*`, они наследуются в Shadow DOM.

**Чего расширению делать нельзя:**
- наблюдать весь `document.body` и опрашивать DOM таймером;
- мутировать их кэш и писать в их ключи `chat-space:*`;
- провоцировать `focus/blur/visibilitychange`, чтобы не вызвать волны перезапросов;
- держать тяжёлую логику в контексте страницы: там только тонкий мост, логика и UI — в изолированном скрипте;
- грузить историю чужих чатов (§3).

## 5. Что ChatSpace уже умеет и где он конкурирует с нами

| Наша функция | В ChatSpace |
|---|---|
| Подсказки ответов | **есть**: AI Suggestions, 10 стилей (Engage, Bump, Spicy, PPV, Upsell…) плюс свои стили на своей модели через OpenRouter со своим промптом. Reasoning выключен всегда, в промпт идут только `{chatHistory}` и `{lastFanMessage}` |
| Онлайн-спендеры | есть, даже шире: Fans Online с buying power, последней покупкой и быстрым ответом |
| Уведомления | есть, но без своих звуков и без push при закрытой вкладке |
| Галерея, vault, PPV | есть, шире нашего |
| Саммари фана | частично: только данные. Вкладка Recap в новой панели готовится |
| Пинги, реактивация | частично: стиль Bump, шаблоны, отложенные сообщения, авто-кампании. Анализа «кого пинговать» нет |
| Доска спендеров | частично: тиров и дат контакта нет |
| Улучшение текста, коучинг, разбор чата | нет |
| Хоткеи для AI | нет |

У ChatSpace есть то, чего нет у нас:
- Mimic — автономный AI-бот, который сам пишет фанам (5 кредитов за сообщение). У нас выключен;
- переводчик;
- Message Guard;
- оценки фана: temperature, reach, focus, buying power 0–5, риск чарджбэка;
- журнал «кто из чаттеров что отправил» и архив отозванных сообщений;
- кампании из чата, шаблоны с медиа, поиск в vault по содержимому картинки, редакторы фото и видео, голосовые.

Каждое сообщение уходит с отметками «скопировано», «из шаблона», «похоже на их AI». По ним OnlyMonster считает метрики команды. Текст, вставленный нашим расширением через мост, никак не помечается.

**Куда они идут** (по флагам Unleash, это система фичефлагов):
- AI-команда строит переводчики и подсказки со своими промптами;
- следующий шаг ChatSpace — боковая панель с вкладками Recap и AI;
- появляется Telegram.

Через несколько месяцев встроенный AI OnlyMonster может закрыть часть того, что делаем мы. Наше преимущество:
- персоны и досье на хабе;
- коучинг и разбор чата;
- проверенные промпты с рассуждением на максимуме;
- данные хаба о тратах по всем платформам.

## 6. Перенос функций Fansly-расширения

| Функция Fansly-расширения | На ChatSpace | Как |
|---|---|---|
| Reply с тонами и Split, Fix, Hi, Ping | да | хаб, полоса «контекст собирает хаб» (как десктоп); вставка через мост; Fix читает черновик из редактора |
| Review, Recap (полный/короткий, синхронизация в хаб), Coach, Help | да | те же фичи хаба; Recap для OnlyFans хаб уже собирает из архива (Scan в десктопе) |
| Тулбар над полем ввода, результат с карточками частей, Enter — следующая часть | да | слот моста + своя панель в Shadow DOM |
| Хоткеи `@chatgoose/hotkeys` | да | перехват в capture-фазе (§4) |
| Доска Spenders | да | ранжирование с хаба (`pageTopSpenders`), переход в чат через `$router.push`. Превью переписок других фанов — только из архива хаба, не из ChatSpace (§3) |
| Новые фоловеры | частично | у OnlyFans своя модель подписчиков. Приветствие — через открытие чата и вставку, а не прямую отправку |
| Voice (скрипт → озвучка → MP3 в сообщение) | позже | вложения в ChatSpace идут через их vault и загрузчик; нужно отдельное исследование `insertMessage` и права Media Uploader |
| Vault-загрузчик | не нужен | у OnlyMonster свой vault и загрузчик |
| Звук входящих и фоловеров | да | событие WebSocket или подписка на хранилище |
| Popup с квотой, настройки, персоны и маппинг аккаунтов | да | маппинг аккаунта OnlyMonster на страницу хаба по `platform_account_id`/username |

## 7. ChatSpace + расширение против десктопа

**Плюсы:**
- **Не нужен свой чат-клиент.** Инбокс, тред, медиа, vault, PPV, шаблоны, переводчик, уведомления делает OnlyMonster и выпускает обновления каждый день. У нас уходят синк (около 7,7 тыс. строк), локальная зашифрованная БД, outbox, обработка картинок.
- **Уходит вся цена Electron.** Нативный SQLCipher, сборка только на Windows, неподписанные билды (SmartScreen), свой фид обновлений, связка релиза с контракт-хешем хаба, 64 релиза за 3,5 месяца. Инциденты: «не запускается» в 0.1.30/31, ночь с PPV poison loop на ~14 тыс. кредитов, изоляция ключа после обновления.
- **Уходят кредиты OFAPI на чтение с машин чаттеров** — около 12,8 тыс. за 28 дней, по прошлой неделе это порядка $40–45 в месяц. Главное — пропадает целый класс инцидентов «клиент жжёт кредиты».
- **Скорость.** Сообщения приходят меньше чем за секунду вместо задержки вебхуков OFAPI в 3–10 минут (данные прода). Пропадает «пустая история» из-за DPI-троттлинга нашего российского сервера к OFAPI.
- **Фонового авто-прочтения больше нет:** ChatSpace читает только открытый человеком чат.
- **Больше данных в чате:** оценки фана, buying power, кто из чаттеров что отправил.
- **Работает на любой ОС в обычном браузере.** Одно расширение потом обслуживает и Fansly.
- **Чаттеры и так работают в OnlyMonster**, в истории видно «Sent by …» с именами наших чаттеров.

**Минусы и риски:**
- **Чужой интерфейс в бете меняется по несколько раз в день.** Любая надстройка хрупкая. Лечится адаптером, проверкой контракта при старте, деградацией вместо поломки и ежедневной канарейкой (§8).
- **Правила OnlyMonster.** Пункт 2.1(d) Terms запрещает reverse engineering; за нарушение — приостановка или удаление аккаунта (2.3). Явного запрета расширений нет. Технически расширение, которое читает память страницы и не шлёт своих запросов, для OnlyMonster невидимо, но юридический риск остаётся (§9).
- **Зависимость от вендора.** Если OnlyMonster лёг или сменил интерфейс, встал и чат. Хотя десктоп тоже зависел от OFAPI.
- **Внутри OM Browser расширения не ставятся.** Чаттер должен работать в ChatSpace в обычном браузере и теряет там нативные виджеты OM (карточку фана и заметки) и системные уведомления. Карточку можно отдать нашей панелью.
- **Два входа и два набора прав.** У чаттера аккаунт OnlyMonster и аккаунт ChatGoose, плюс третье пространство id (аккаунт OnlyMonster).
- **Пропадают вещи десктопа, которых нет в ChatSpace:**
  - `[NEXT]`-цепочки (отправка частями с паузой);
  - мини-чат Spenders с отправкой;
  - офлайн-кэш.
- **AI-контекст для OnlyFans зависит от OFAPI-архива хаба.** Если OFAPI отключить, контекст перестанет обновляться. Даже с OFAPI он отстаёт от того, что чаттер видит в ChatSpace (§8, «Две полосы контекста»).
- **Встроенный AI OnlyMonster растёт** и в части функций будет конкурировать с нашим.

Есть промежуточный вариант: Electron загружает ChatSpace в своё окно (запрет касается только iframe) и встраивает наши панели. Синк, БД и отправка уходят, но вся цена Electron остаётся. Имеет смысл, только если расширение не получится раздать чаттерам.

## 8. Архитектура нового расширения

**Принципы:**
1. Ядро не знает, где оно живёт. Всё, что зависит от хоста, — за интерфейсом порта хоста (HostPort).
2. Две независимые оси: **хост** (ChatSpace, fansly.com) и **платформа** (OnlyFans, Fansly). Сейчас ChatSpace — это OnlyFans, позже, возможно, и Fansly.
3. AI только на хабе. Промпты и модели не уходят в клиент.
4. Отправку делает только человек родной кнопкой хоста. Расширение вставляет черновик, никогда не жмёт Send, никогда не повторяет отправку.
5. Расширение не нагружает хост:
   - читаем их кэш и подписываемся на события;
   - своих запросов к OnlyMonster по умолчанию не делаем;
   - DOM не наблюдаем целиком.
6. Деградация вместо поломки:
   - при запуске адаптер проверяет «контракт хоста»: есть ли нужные хранилища, ключи кэша, мост, роутер;
   - если что-то не совпало, выключает затронутые функции, показывает чаттеру понятное сообщение и шлёт отчёт в хаб;
   - удалённый конфиг (имена ключей, селекторы, флаги) — это данные, не код.

**Слои:**
- `core/` — чистый TypeScript:
  - модели и сценарии: reply, fix, hi, ping, review, recap, coach;
  - клиент хаба (`@kernel/sdk`, поток SSE, реестр ошибок CG-*), движок хоткеев, состояние, телеметрия, квота, персоны.
- `hosts/chatspace/`:
  - тонкий мост в контексте страницы (роутер, Pinia, кэш, `__omComposerBridge`, пассивное чтение WebSocket);
  - изолированная часть: нормализация, проверка контракта, точки монтирования.
- `hosts/fansly/` — перенос проверенных Fansly-модулей за тот же порт: запросы к apiv3 на снятой сессии, пейсер, PPV, фоловеры, vault, вставка.
- `ui/` — панели в Shadow DOM, тема повторяет хост.
- `background/` — вход по device token (D35), транспорт к хабу, кэш, обновления, удалённый конфиг.

Подробный интерфейс HostPort с покрытием всех текущих функций — в [fansly-extension.md, §7.3](onlymonster-chatspace/fansly-extension.md).

**Две полосы контекста для AI.**
- Сейчас хаб принимает контекст, собранный клиентом (`clientContext`), только для Fansly (`hub/apps/runtime/src/modules/ai/features/index.ts:468`). Для OnlyFans он отвергает такой контекст и берёт переписку из своего архива. Десктоп шлёт только ссылки: страница, id фана, персона, тон, черновик.
- Поэтому в ядре два режима:
  - **«собирает хаб»** — OnlyFans: шлём ссылки, работает сразу, без доработок хаба;
  - **«собирает клиент»** — Fansly: шлём живую переписку.
- Следующий шаг для качества — разрешить в хабе живой контекст из ChatSpace и для OnlyFans. Тогда AI видит последнее сообщение фана сразу, а не после прихода вебхука OFAPI, и OFAPI для AI перестаёт быть обязательным. Это работа на стороне хаба: снять ограничение и добиться одинакового формата транскрипта.

**Стек:**
- **WXT** — фреймворк для расширений на Vite. Одна кодовая база собирается в Firefox и Chrome (MV3), есть HMR, манифест типизирован.
- **TypeScript strict, zod** на всех границах: мост, ответы хаба, данные хоста.
- **React** — как в десктопе. Поверхности десктопа (AI-док, доска Spenders, панель фана) уже отвязаны от Electron интерфейсом `ChatGooseBridge` и запускаются в браузере. Их можно перенести в Shadow DOM, а не писать заново. Если важен минимальный размер, подойдёт Preact с compat: панели маленькие, узкое место не фреймворк, а наблюдение за страницей.
- **В контексте страницы — только тонкий мост без зависимостей.** Логика и UI — в изолированном скрипте и фоне.

**Проверки:**
- контрактные тесты адаптера на обезличенных снимках реальных форм данных ChatSpace;
- e2e на Playwright с подставной страницей;
- **канарейка**: ежедневно сравнивать хеши чанков `chat.onlymonster.ai` и при изменении прогонять проверку контракта на тестовом аккаунте, чтобы узнать о поломке раньше чаттеров.

**Раздача:**
- **Firefox** — как сейчас Fansly-расширение: подпись AMO unlisted и свой фид обновлений на `ext.gosling-agency.ru`. Конвейер уже есть, чаттеры уже в Firefox. Нужно проверить, что ChatSpace нормально работает в Firefox (§10).
- **Chrome Web Store**, скорее всего, отклонит: правила запрещают расширения, «предназначенные для улучшения сайтов с откровенным контентом», и для unlisted они те же.
- **Вне магазина** Chrome ставит расширение только на компьютеры в домене AD/Azure AD или записанные в бесплатный Chrome Enterprise Core. Это реально для компьютеров агентства, но браузер станет «управляемым организацией».

## Независимая проверка: Codex

То же задание параллельно выполнял Codex (GPT-6-Astra, max), не видя этого документа. Его отчёт и обезличенные доказательства (только формы данных и хеши бандлов) лежат в [`onlymonster-chatspace/codex/`](onlymonster-chatspace/codex/report.html).

**Совпало:** «да» на все три вопроса. Стек Vue + Clerk + TipTap + WebSocket, iframe и защиты нет. ChatSpace показывает только OnlyFans и Telegram, хотя Fansly-аккаунт API уже знает. Отправку оставляем родной кнопке. С нуля пишем оболочку и адаптеры, переиспользуем SDK хаба, хоткеи и проверенные правила, Fansly подключаем вторым адаптером. Пилот обходится без доработок хаба. OFAPI в хабе остаётся: на нём архив и деньги.

**Что добавил Codex:**
- Уведомления при закрытой вкладке не гарантированы: service worker ChatSpace (`notifications-sw.js`) обрабатывает только клик по уведомлению, Web Push в исходнике помечен TODO.
- По документации OnlyMonster аккаунт подключается через OM Browser. Как ChatSpace переживает холодный старт и повторный вход в OnlyFans, пока OM Browser закрыт, никто не проверял.
- Короткая страница истории не означает её конца: запрос на 60 сообщений вернул 58 при `has_more=true`.
- Живой контекст ChatSpace для OnlyFans (этап 3 плана) нельзя получить простым снятием ограничения `clientContext`. Ограничение защищает от подделки переписки и трат клиентом. Нужен отдельный контракт о происхождении данных: источник, время получения, покрытие истории, лимиты. Деньги остаются серверными.
- Вебхуки публичного API OnlyMonster теряют события, если доставка надолго приостановлена из-за таймаутов получателя. Если брать их источником для хаба, нужна сверка через API.

**Чего нет у Codex, но есть здесь:** проверенное вживую прочтение при открытии (§3), мост `__omComposerBridge` и прототип вставки, пункт 2.1(d) правил OnlyMonster, конфликты хоткеев, ограничения Chrome на раздачу расширения. Отправку, PPV, голос и загрузки не испытывал ни один из двух.

В доказательствах Codex `mimicSettings.isActive = true` — это переключатель организации. На аккаунте Mimic выключен (сервер отвечает 400 «Mimic is disabled for account»), противоречия с §5 нет.
