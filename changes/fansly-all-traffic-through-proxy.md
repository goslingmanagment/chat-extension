# Весь трафик модели теперь идёт через её прокси

Раньше часть запросов уходила мимо прокси контейнера, с вашего адреса: сам сайт Fansly после первой загрузки, FBuddy и запросы ChatGoose. Из-за этого Fansly видел рядом с адресом модели ваш, а без VPN сайт мог не открываться. Теперь всё это идёт через прокси модели, и VPN для Fansly больше не нужен.

Нужно один раз разрешить. На вкладке Fansly появится подсказка: нажмите «Разрешить», затем «Разрешить» в настройках и в окне Firefox. Firefox спросит доступ ко всем сайтам: через прокси идёт всё, что открывает вкладка модели. Настраивать прокси заново не нужно, ChatGoose берёт его сам. Пока не разрешите, всё работает как раньше.

## Как это устроено

Multi-Account Containers ставит прокси контейнера только на запросы с вкладкой, а у service worker Fansly, контент-скрипта FBuddy и фона расширения вкладки нет, поэтому они шли напрямую. Firefox всё равно называет контейнер такого запроса, и теперь их маршрутизирует ChatGoose: прокси страницы берёт из хаба, контейнер узнаёт по аккаунту вкладки. Запрос самого расширения без прокси с вашего адреса не уходит: только через вкладку модели, а без неё не уходит вообще. Если прокси не отвечает, запрос завершается ошибкой, а не идёт напрямую.
