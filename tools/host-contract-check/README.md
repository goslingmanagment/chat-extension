# Сверка контракта хоста с локальным бандлом

Инструмент читает файлы с диска; запросов к сайтам и исполнения их кода нет.
Чужие бандлы остаются вне Git и исходного архива расширения.
В `pnpm check` и CI входят тесты с **синтетическими** текстами, включая запуск CLI.
Саму сверку настоящего снимка выполняют локально после смены сборки сайта.

Для ChatSpace прежняя команда и проверки профиля отправки / телеметрии сохранены:

```sh
node tools/host-contract-check/index.ts --host chatspace --dir <копия/pretty> --json
```

Для Fansly (R20 P7h, архитектура §7.7, §7.12; FS-CTR-1, FS-CTR-3):

```sh
node tools/host-contract-check/index.ts --host fansly --dir <снимок/pretty> --json
node tools/host-contract-check/index.ts --host fansly --dir <новый/pretty> --against <старый/pretty>
```

`fansly-web` — равнозначное имя из реестра хостов. Без `--dir` переменная
`CG_FANSLY_BUNDLES` задаёт сам снимок с `pretty/`, его `pretty/` либо родительскую
папку снимков с датой `YYYY-MM-DD` в конце имени: выбирается самая поздняя дата.
Читаются JS, CSS и HTML, включая вложенные папки. Симлинки не обходятся.
Признаки Fansly засчитываются только в `main.<hash>.js` и числовых lazy chunks
`<номер>.<hash>.js`: похожий код видеоплеера, графиков, service worker или CSS их не заменяет.
Расположение снимка 2026-10-12 — в [указателе исследования](../../docs/research/fansly.md#2-бандл-и-все-собранные-материалы).

`anchors-fansly.ts` берёт ожидаемые группы из `FANSLY_CONTRACT`, DOM-селекторы —
из P7c/P7d `isolated/anchors.ts`. У каждой группы одна или несколько проверок;
пройти должны **все**, включая vault. Вывод содержит только имена проверок,
`файл:строка`, число совпадений и отпечаток `main.<hash>`. Для нескольких разных
`main` отпечаток неизвестен (`null`). С `--against` выводятся смена отпечатка и
изменения наличия якорей. Профиль квитанции и tripwire ChatSpace к Fansly не применяются.
Код возврата Fansly: `0` — все проверки пройдены, `1` — хотя бы один якорь отсутствует.

Это статические признаки: например, для поля проверяются литерал `textarea` и
класс `message-input`; для сокета — адрес, версия и конструктор. Наличие строк
не доказывает цепочку DOM, активность соответствующей ветки кода, форму реального
ответа или работу Firefox MV3. Это проверяют стенд и пилот. Новый хеш сам по себе
не означает поломку (FS-CTR-3), а отсутствие ожидаемого признака требует разбора.

Отдельные отрицательные фикстуры проверяют `FanslyContractBlockSchema`,
`FanslyContractReportSchema` и `contractFactsOf(report, FANSLY_CONTRACT)`:
нет блока или любого ключа якоря — отчёт не зелёный. Явное `vaultUpload: missing`
вне страницы vault допустимо; отсутствие самого ключа — неполный отчёт.
